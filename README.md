# Darwin Knowledge Platform Backend

## Snowflake ID

`users.id` is generated by the FastAPI application with a 63-bit
Snowflake layout: 41 timestamp bits, 10 worker bits, and 12 sequence
bits. API JSON and JWT `sub` values carry user IDs as decimal strings
so browser JavaScript never receives large IDs as JSON numbers.

Configure:

```env
SNOWFLAKE_WORKER_ID=1
SNOWFLAKE_EPOCH_MS=1767225600000
```

`SNOWFLAKE_EPOCH_MS=1767225600000` is 2026-01-01 00:00:00 UTC. Once it
has been used for production data, do not change it. Every independent
application instance must use a unique `SNOWFLAKE_WORKER_ID` in the
range 0-1023. For the MVP, run a single Uvicorn worker unless a
worker-id allocation plan exists; starting multiple workers with the
same worker ID can create duplicate IDs.

基于 FastAPI、SQLAlchemy 和 MySQL 的知识平台后端。当前基础版本提供运行状态检查和 User CRUD，后续知识入库能力将在独立 OpenSpec change 中扩展。

## 环境要求

- Python 3.11
- MySQL 8

## 初始化

```powershell
conda activate kb
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

如果需要重新创建项目环境，可执行 `conda create --name kb python=3.11`。编辑 `.env`，填写本地 MySQL 连接信息。`.env` 只用于本地开发，不应提交到 Git。

## 数据库迁移

```powershell
alembic upgrade head
```

聊天附件功能会创建 `attachments` 和 `message_attachments` 表。文件二进制只保存到私有 MinIO bucket，数据库只保存元数据和消息关联。

`upgrade` 用于空数据库。如果数据库中已经存在与当前模型一致的 `users` 表，应先核对表结构，然后仅登记迁移基线：

```powershell
alembic stamp head
```

不要对已有 `users` 表直接执行首次 `upgrade`，否则 Alembic 会尝试重复建表。

回退最近一次迁移：

```powershell
alembic downgrade -1
```

## 启动 API

```powershell
uvicorn app.main:app --reload
```

默认入口：

- API 文档：`http://127.0.0.1:8000/docs`
- 存活检查：`http://127.0.0.1:8000/health/live`
- 就绪检查：`http://127.0.0.1:8000/health/ready`
- User API：`http://127.0.0.1:8000/api/v1/users`

## 聊天附件

先上传附件，再在聊天请求里引用返回的 `attachment_id`：

```http
POST /api/attachments
Authorization: Bearer <token>
Content-Type: multipart/form-data

file=<binary>
conversation_id=<optional uuid>
purpose=chat_attachment
```

成功响应的 `data.preview_url` 为 `/api/attachments/{attachment_id}/content`。MinIO bucket 必须保持私有，后端会在内容接口中鉴权后转发文件内容。

支持图片 `.jpg`、`.jpeg`、`.png`、`.webp`，文档 `.pdf`、`.txt`、`.md`、`.csv`、`.json`、`.html`、`.htm`。默认限制：单张图片 10 MB、单个文档 5 MB、单条消息最多 4 个附件、附件总大小 15 MB。

OpenClaw 调用策略：

- 无附件或仅图片附件：继续走 `/v1/chat/completions`。图片以 `image_url.url = data:<mime>;base64,...` 传入。
- 文本类附件 `.txt`、`.md`、`.csv`、`.json`、`.html`、`.htm`：后端从 MinIO 读取并解码为文本，作为 `/v1/chat/completions` 的 `text` 段内联传入。
- PDF 附件：后端从 MinIO 读取后先用 `pypdf` 抽取前若干页文本，再作为 `/v1/chat/completions` 的 `text` 段内联传入；如果抽到的文字太少，再用 `PyMuPDF` 把前几页渲染成 PNG，并以 `image_url` 一并发给视觉模型。
- 不向 OpenClaw 传 MinIO URL，后端始终从私有 MinIO 读取 bytes 后转 Base64。

聊天请求示例：

```json
{
  "conversation_id": "00000000-0000-0000-0000-000000000000",
  "message": "请分析这张图片",
  "attachment_ids": ["attachment-uuid"],
  "stream": true
}
```

新增配置：

```env
MINIO_ENDPOINT=127.0.0.1:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET_CHAT_ATTACHMENTS=chat-attachments
MINIO_SECURE=false
MINIO_REGION=
ATTACHMENT_IMAGE_MAX_SIZE=10485760
ATTACHMENT_DOCUMENT_MAX_SIZE=5242880
ATTACHMENT_TOTAL_MAX_SIZE=15728640
ATTACHMENT_MAX_COUNT=4
ATTACHMENT_IMAGE_MAX_PIXELS=40000000
ATTACHMENT_INLINE_TEXT_MAX_CHARS=60000
ATTACHMENT_PDF_MAX_PAGES=20
ATTACHMENT_PDF_TEXT_MIN_CHARS=120
ATTACHMENT_PDF_RENDER_MAX_PAGES=3
ATTACHMENT_PDF_RENDER_ZOOM=1.5
```

## 测试

测试必须使用独立 MySQL 数据库。测试数据库名必须以 `_test` 结尾或以 `test_` 开头，防止误写普通运行数据库。

```powershell
$env:TEST_DATABASE_URL = "mysql+pymysql://root:password@127.0.0.1:3306/darwin_knowledge_test?charset=utf8mb4"
pytest
```

测试会对专用数据库执行 Alembic 迁移并清理测试数据。未提供安全的 `TEST_DATABASE_URL` 时，集成测试会在数据库写入前失败。
