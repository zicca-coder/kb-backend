# Darwin Knowledge Platform Backend

## Snowflake ID

`users.id` is generated by the FastAPI application with a 63-bit
Snowflake layout: 41 timestamp bits, 10 worker bits, and 12 sequence
bits. API JSON and JWT `sub` values carry user IDs as decimal strings
so browser JavaScript never receives large IDs as JSON numbers.

Configure:

```env
SNOWFLAKE_WORKER_ID=1
SNOWFLAKE_EPOCH_MS=1767225600000
```

`SNOWFLAKE_EPOCH_MS=1767225600000` is 2026-01-01 00:00:00 UTC. Once it
has been used for production data, do not change it. Every independent
application instance must use a unique `SNOWFLAKE_WORKER_ID` in the
range 0-1023. For the MVP, run a single Uvicorn worker unless a
worker-id allocation plan exists; starting multiple workers with the
same worker ID can create duplicate IDs.

基于 FastAPI、SQLAlchemy 和 MySQL 的知识平台后端。当前基础版本提供运行状态检查和 User CRUD，后续知识入库能力将在独立 OpenSpec change 中扩展。

## 环境要求

- Python 3.11
- MySQL 8

## 初始化

```powershell
conda activate kb
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

如果需要重新创建项目环境，可执行 `conda create --name kb python=3.11`。编辑 `.env`，填写本地 MySQL 连接信息。`.env` 只用于本地开发，不应提交到 Git。

## 数据库迁移

```powershell
alembic upgrade head
```

`upgrade` 用于空数据库。如果数据库中已经存在与当前模型一致的 `users` 表，应先核对表结构，然后仅登记迁移基线：

```powershell
alembic stamp head
```

不要对已有 `users` 表直接执行首次 `upgrade`，否则 Alembic 会尝试重复建表。

回退最近一次迁移：

```powershell
alembic downgrade -1
```

## 启动 API

```powershell
uvicorn app.main:app --reload
```

默认入口：

- API 文档：`http://127.0.0.1:8000/docs`
- 存活检查：`http://127.0.0.1:8000/health/live`
- 就绪检查：`http://127.0.0.1:8000/health/ready`
- User API：`http://127.0.0.1:8000/api/v1/users`

## 测试

测试必须使用独立 MySQL 数据库。测试数据库名必须以 `_test` 结尾或以 `test_` 开头，防止误写普通运行数据库。

```powershell
$env:TEST_DATABASE_URL = "mysql+pymysql://root:password@127.0.0.1:3306/darwin_knowledge_test?charset=utf8mb4"
pytest
```

测试会对专用数据库执行 Alembic 迁移并清理测试数据。未提供安全的 `TEST_DATABASE_URL` 时，集成测试会在数据库写入前失败。
